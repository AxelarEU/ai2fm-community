# ai2fm v2.5

**FileMaker Clipboard Bridge 2.5.0** · released October 2026 · VS Code, Cursor, Devin, Antigravity, Kiro, VSCodium, TRAE and Qoder, on Windows (x64) and macOS (Intel).

Copy a FileMaker script, read it as text in your editor, change it, and paste it back. v2.5 is the biggest release since ai2fm began. This page lists everything that changed since v2.4 (2.40.0, May 2026).

## At a glance

1. **The Import Records step, as text.** It is one name in the Script Workspace and four steps behind it. All four sources round-trip.
2. **The `.fmscript` standard, one page per step**, at [fmscript.org](https://fmscript.org). 24 pages are published so far, hardest first.
3. **The ai2fm Agent Pack, the ai2fm Corpus for AI Agents.** Every published page in full, with every example script and the FileMaker files they run in. It is installed into the extension, and your AI agent reads it.
4. **Help that pastes.** Every example in the built-in help of every script step is now valid `.fmscript`, ready to paste into FileMaker.
5. **Autocomplete built from the standard:** 20 steps and 76 ready-made forms, plus option lists for the JSON functions and every Claris function.
6. **A formatter that lays steps out the way a person would**, for SQL, calculations, JSON and windows. It never changes a value.
7. **Print steps, readable at last.** The printer, records, page range, orientation, paper and scale of every Print, Print Setup and Print PDF step, written out in text for you and your AI agent. No other tool we know of does this.
8. **Conversion runs on the ai2fm server.** Every conversion fix reaches you the moment it is published, with no update to install.
9. **The ai2fm panel** in the left-hand bar, buttons above every script, and **FileMaker 2025 or 2026** as the version you paste into.
10. **Protection from FileMaker's own clipboard bugs.** ai2fm repairs what it can and warns you on the step where it cannot.
11. **Layouts and layout objects** travel through the clipboard both ways, on Mac and Windows.
12. **Compiled, licensed and private.** Your scripts are never stored, and your licence key lives in your operating system's secret storage.

## The Import step, as text

In May 2024, on the Claris Community, Clay Maeckel, Chief Software Architect at Claris, wrote:

> "I'd like to see someone write what a textual version of the import script step would be."

Import Records is one name in the Script Workspace and four steps behind it: **from a file, a folder, an ODBC data source, or XML.** Each source has its own options and its own field mapping. In v2.5 each is written out in full:

```
Import Records [
    With dialog: Off;
    Source: "file:fixtures/Import_Sources/Import_Records_Source.fmp12";
    File Type: FileMaker;
    Source table: 129 (1065089);
    Target: "myTable";
    Method: UpdateOnMatch;
    Field Mapping:
    Source field 1 import to myTable::PrimaryKey;
    …
    Source field 6 match with myTable::__pkMyTableID;
    …
    Source field 9 not import to myTable::myTextNumber;
]
```

This is an update on a match field that leaves one field untouched, shortened here.

- **All four sources round-trip**, text to FileMaker and back.
- **The language writes only what FileMaker's dialog lets you set.** `First row`, `Predefined` and the delimiter appear only for the file types where FileMaker offers them.
- **Calculations are kept exactly as written**, character for character.
- **Each source has its own page** at fmscript.org.
- **Help opens the right page.** With the cursor on an Import Records step, Script Step Help opens the page for the source the step uses. When no source is written yet, it offers the four.

## Print steps, readable at last

**No other tool we know of shows what a FileMaker print step holds.** FileMaker stores the settings of a Print, Print Setup or Print PDF step as the printer driver's own binary block. The Script Workspace shows the printer's name and little else, and FileMaker's own script printout leaves the scale out for most printers.

Here is FileMaker's printout of three Print steps, each set to a different scale on a different printer:

```
Print [ Records being browsed; All Pages; Orientation: Portrait; Paper size: 8.26" x 11.69" ]
[ Restore: Brother HL-EX470 series; No dialog ]
Print [ Records being browsed; All Pages; Orientation: Portrait; Paper size: 8.26" x 11.69" ]
[ Restore: Canon iX7000 series; No dialog ]
Print [ Records being browsed; All Pages; Orientation: Portrait; Paper size: 8.26" x 11.69" ]
[ Restore: EPSON L365 Series; No dialog ]
```

And the same three steps in ai2fm v2.5:

```
Print [ Restore: Brother HL-EX470 series ; Records being browsed ; All Pages ; Collate: Off ; Orientation: Portrait ; Paper size: 8.27" x 11.69" ; Scale: Fit to Paper Size ; With dialog: Off ; PrintSettings: #blob … ]
Print [ Restore: Canon iX7000 series ; Records being browsed ; All Pages ; Collate: Off ; Orientation: Portrait ; Paper size: 8.27" x 11.69" ; Scale: 65% ; With dialog: Off ; PrintSettings: #blob … ]
Print [ Restore: EPSON L365 Series ; Records being browsed ; All Pages ; Collate: Off ; Orientation: Portrait ; Paper size: 8.27" x 11.69" ; Scale: 94% ; With dialog: Off ; PrintSettings: #blob … ]
```

### What ai2fm reads

- **The printer**, and on the Mac **Any Printer** when the step is formatted for no particular printer.
- **The records:** records being browsed, the current record, or a blank record (as formatted, with boxes, with underlines, with placeholder text).
- **The pages:** all pages or a page range, the first page number, copies and collation.
- **The page:** orientation and paper size.
- **The scale, read from each printer driver.** Every Windows printer family stores the scale in its own place, and ai2fm reads each one: Adobe PDF, Xerox, HP, HP Universal, EPSON, Canon and Brother, including modes such as Fit to Paper Size. Drivers with no scaling at all (Zebra, OneNote, Microsoft Print to PDF) get no scale line, rather than an invented one. On the Mac, the scale comes from the page format itself.

Every reading was checked against each printer's own settings dialog, on Windows and on the Mac.

### Nothing is lost on the way back

The readable values are for you and your agent. The original print settings travel with the step, sealed (`#blob`), so a step you paste back into FileMaker prints exactly as before. Every driver setting, including the ones no text shows (tray, paper type, two-sided printing), comes back byte for byte. To change a print option, use FileMaker's Print Setup dialog after pasting.

### What it gives developers and AI agents

- **Review print changes like any other change.** A different printer, paper or scale is one changed word in a git diff, instead of an unreadable block.
- **Ask your agent about printing.** An AI agent reading the script sees which printer, paper and scale each step uses, without anyone opening a dialog.
- **The Agent Pack** holds the full Print, Print Setup and Print PDF pages, with their examples and the FileMaker files they come from.

## The .fmscript standard

[fmscript.org](https://fmscript.org) publishes the `.fmscript` language one page per step. Each page gives:

- the step's full text syntax and every parameter;
- the order the parameters are written in;
- the writing rules;
- one example.

**24 pages, covering 21 FileMaker steps, are published so far, hardest first.** Import Records has one page per source:

| Family | Pages |
|---|---|
| Import and export | Import Records from File · from Folder · from ODBC · from XML · Export Records · Convert File |
| PDF (FileMaker 2026) | Create PDF · Open PDF · Append PDF · Close PDF · Cancel PDF · Print PDF · Save Records as PDF |
| Printing | Print · Print Setup |
| SQL | Execute SQL |
| Windows and navigation | New Window · Go to Related Record · Go to List of Records |
| Sorting | Sort Records · Sort Records by Field |
| Input and dialogs | Show Custom Dialog · Insert from Device · Insert from URL |

- Every rule on those pages was checked against FileMaker itself.
- The converter handles every FileMaker step today; the pages follow, one step at a time.
- As each new page is published, its help, autocomplete and checking arrive in the extension.
- **A free sample:** the [Execute SQL page](https://axelareu.github.io/ai2fm-community/fmscript-standard/execute-sql/execute-sql.html) is published complete, so you can see what the Agent Pack includes.

The standard is public to read. All rights are reserved; to implement it in your own tool, talk to us first.

## The ai2fm Agent Pack

**The ai2fm Agent Pack, the ai2fm Corpus for AI Agents**, is included with a licence. For every published step it holds:

- the full page, with every example and the reasoning behind each rule;
- the example scripts themselves, commented and runnable;
- the FileMaker files and fixtures they run in.

Today that is **24 pages, 283 example scripts and 33 FileMaker files**, and it grows with each step we publish.

### In your editor

- **Install Agent Pack…** in the ai2fm panel (Help group) installs the pack from its ZIP file.
- **The pack is checked whole before anything changes.** Every file is checked against the pack's own inventory and checksums. If anything is wrong, nothing changes and your installed pack stays as it was.
- **Script Step Help, and the "Open full step help…" link in the hover,** open the pack's page for that step. Its example and FileMaker-file links open the real files. Steps without a pack page keep the built-in help.
- **Nothing in the pack is ever run.** Opening a page or an example never executes a script, an SQL statement or a FileMaker file.

### For your AI agent

The pack carries instruction files that AI agents and editors read: `AGENTS.md`, `CLAUDE.md`, an Agent Skill, a Cursor rule and a Kiro steering file. Two commands put them in reach:

- **Add to Workspace** makes the installed pack a folder of your workspace. From there your agent finds it: Claude Code, Codex, Cursor, Copilot, Kiro and any agent that reads `AGENTS.md`. When a newer pack is installed, the folder follows it. **Remove from Workspace** takes it out.
- **Copy Agent Pointer** copies one paragraph for your own `AGENTS.md`, `CLAUDE.md` or steering file. It tells your agent where the pack is and how to use it. The pointer names a location that does not change, so it stays right when the pack is updated. ai2fm never writes into your own files.

The pack is reference material for you and your agent. It is never permission to run anything.

## Autocomplete, from the standard

v2.4 had a hand-written list of step snippets, and it drifted from the real language. In v2.5, autocomplete comes from the finished, FileMaker-verified pages: when a page changes, autocomplete follows.

### 20 steps, 76 ready-made forms

| Step | Forms |
|---|---|
| Import Records: from File · XML · Folder · ODBC (SQL) · ODBC (calculated SQL), and with nothing set | 6 |
| Export Records: Excel · text (`.csv`, `.tab`, `.mer`, `.dbf`, `.htm`) · FileMaker Pro · XML, and with nothing set | 5 |
| Convert File: from File · XML · ODBC (SQL) · ODBC (calculated SQL), and with nothing set | 5 |
| Execute SQL: SQL text · calculated SQL text | 3 |
| New Window: Document · Floating Document · Dialog · Card | 4 |
| Go to Related Record · Go to List of Records: current window · new window | 3 + 3 |
| Insert from Device: camera, video, barcode (2), signature, microphone, music, photos | 9 |
| Save Records as PDF: to a file · to a container · to the open PDF · appended | 5 |
| Print · Print PDF (Windows, macOS, from a file path) | 4 + 4 |
| Open PDF · Append PDF · Close PDF · Create PDF | 3 + 3 + 3 + 2 |
| Sort Records · Sort Records by Field · Print Setup | 5 + 3 + 2 |
| Show Custom Dialog · Insert from URL | 2 + 2 |

Every form arrives complete, with every parameter. It is laid out exactly as Step → Multi-Line writes it, and it converts to FileMaker as it stands. Steps without a finished page keep the earlier snippets.

### How it behaves

- **Value lists wherever the cursor is in a value**, as you type and when you come back to a finished step.
- **Only the values FileMaker accepts**, with readable names for invisible ones: **Comma**, **Semicolon**, **Space**, **Tab**.
- **Choices that decide the rest of a step rewrite it:**

  | You choose | The step adapts |
  |---|---|
  | File Type (Import Records, Convert File) | `First row`, `Predefined` and `Delimiter` appear or go, as FileMaker's dialog greys them |
  | Window Style (New Window, Go to Related / List of Records) | the flags become that style's flags: Card gets Close and Dim parent window, Dialog has no Minimize |
  | From / Save to (Open, Append, Close PDF, Save Records as PDF) | the branch's own lines replace the other branch's |
  | Predefined: Yes / No | Yes sets the type's own delimiter; No leaves a placeholder until you type one character |
  | dBASE | Character Set becomes DOS OEM, one of the two dBASE accepts |
  | Export Records as FileMaker Pro | no Character Set: FileMaker fixes it to UTF-16 |

- **JSON types:** at the `type` of JSONSetElement (as an argument and in every `[ ]` entry) and of JSONMakeArray, the list offers `JSONString`, `JSONNumber`, `JSONObject`, `JSONArray`, `JSONBoolean`, `JSONNull` and `JSONRaw`.
- **Every Claris function at Set Variable's `Value:`.** Click the placeholder, or a single word, and the list opens. The function you pick replaces the word.
- **Details that save typing:**
  - the layout name in parentheses follows the layout you type;
  - Go to List of Records offers its five record-ID forms;
  - Field Mapping offers `import to`, `match with` and `not import to`.

## Readable steps: the formatter

Right-click a step: **Step → Multi-Line** lays it out, **Step → Single Line** folds it back. **Format Document** tidies the whole file. **The formatter never changes a value**: strings, quoted names with `;` inside, AppleScript and literal SQL stay exactly as written.

| What | Where |
|---|---|
| SQL laid out by clause: `SELECT`, `FROM`, `WHERE`, one column per line, `CREATE TABLE` | Execute SQL, Import Records and Convert File from ODBC |
| `Let` calculations laid out like hand-formatted ones | calculated SQL, XML and XSL from a calculation |
| A calculation you already laid out keeps its line breaks | Set Variable, Show Custom Dialog |
| A one-line calculation breaks after each `¶`, with `&` at the end of the line | Set Variable, Show Custom Dialog |
| JSONSetElement: one `[ ]` entry per line, in aligned columns | any calculation |
| `Field Mapping:` on its own line, then one mapping per line | Import Records, Convert File |
| Export Records' fields, one per line | Export Records |
| The second bracket group (the new window, the PDF options) laid out too | Go to Related Record, Go to List of Records, Save Records as PDF, Create PDF |

A `[` inside a comment no longer stops Format Document.

## Checking as you type: the linter

Problems appear in the Problems panel while you type, before you convert.

- **Brackets:** only real brackets count, never those inside strings, comments or calculations.
- **Import and Convert File delimiters:**
  - with `Predefined: Yes`, the delimiter must be one of FileMaker's;
  - with `Predefined: No`, it must be exactly one character.
- **dBASE character sets:** only DOS OEM or Shift JIS.
- **Aggregate functions with a single non-field argument.** List, Sum, Average, Count, Max, Min, StDev, StDevP, Variance and VarianceP need a field when they get one argument:
  - **a literal** such as `List ( "66" )`: FileMaker refuses it (error 1214) and comments the calculation out on paste;
  - **a lone variable** such as `List ( $names )`: FileMaker accepts it, but returns `<Field Missing>`.
- `<` inside a calculation and `${…}` are no longer reported as errors.

### The ai2fm panel

Click the ai2fm icon in the left-hand bar. Every action is one click away, whatever file is open:

| Group | Rows |
|---|---|
| **Target** | FileMaker 2026 or 2025: click to change |
| **Convert** | Text → FM Clipboard · FM Clipboard → Text · Auto-convert Active Editor · Read FM Clipboard to Editor |
| **Preview XML** | Text → FM XML · FM XML → Text |
| **Tools** | Validate Script Text · Step → Single Line · Step → Multi-Line · Copy with Type Picker… |

A row of buttons sits above every `.fmscript` too: **Text → FM**, **FM → Text**, **Validate**.

### Choose your FileMaker version

**Target** decides which FileMaker the conversion writes for: **2026** or **2025**. Some steps changed their clipboard format between versions, and each FileMaker accepts only its own. ai2fm writes exactly what the version you choose reads.

### Shortcuts

| Action | macOS | Windows |
|---|---|---|
| FM → Text: the FileMaker clipboard as a new script | Cmd+Opt+T | Ctrl+Alt+T |
| **FM → Text at the cursor**, into the script you are editing | Cmd+Opt+I | Ctrl+Alt+I |
| Text → FM: check, then put on the clipboard | Cmd+Opt+F | Ctrl+Alt+F |
| Auto-convert the editor or the selection | Cmd+Opt+Q | Ctrl+Alt+Q |
| Read the FileMaker clipboard as XML | Cmd+Opt+G | Ctrl+Alt+G |
| Copy XML to the FileMaker clipboard | Cmd+Opt+V | Ctrl+Alt+V |

- **Text → FM works only in `.fmscript` files**, so its key no longer fires elsewhere.
- **Fix Conflicting Shortcuts:** when another extension takes one of these keys, ai2fm offers to give it back. It writes the fix in your own key settings, the only place that can.

### Every copy of a script, ready to compare

FM → Text on a whole script creates a file named after the script and the time of the copy, such as `Invoice Totals-2026-10-12T09-24-11-000Z.fmscript`. Successive copies sit side by side, ready for git to show exactly what changed.

### New and changed settings

| Setting | Default | What it does |
|---|---|---|
| Target FileMaker Version | 2026 | The version you paste into: 2026 or 2025 |
| Show Hover Help | On | Help when the pointer rests on a step or a function |
| Warn Layout Table Occurrence | On | One note per script with Go to Layout or Go to Related Record, explaining that the name in parentheses after a layout is the layout's name, not its table occurrence |

The local conversion mode is removed: conversion runs on the ai2fm server.

## Protection from FileMaker's clipboard bugs

FileMaker's own copy and paste loses some values, depending on the step and the FileMaker version.

- **During v2.5 we documented 18 of these defects,** each with test files you can download and reproduce: [FileMaker clipboard bugs](https://axelareu.github.io/ai2fm-community/claris_bugs/claris_clipboard_bugs.html).
- **ai2fm repairs what it can, and warns you on the step where it cannot.** For example, Read from Data File and Set Data File Position lose a value when copied in FileMaker 2026, and ai2fm says so on the step.
- **Version differences are bridged:** the AI account and RAG steps are written the way the FileMaker version you paste into reads them.

## Security and privacy

- **Your scripts are never stored.** Your FileMaker XML and the text ai2fm returns exist only in memory for the length of one request. No disk, no logs, no backups, no AI training. **No AI service is called during conversion.** [Retention policy](https://ai2fm.com/retention.html).
- **Your licence key is kept in your operating system's secret storage**, not in your settings files. It moves there once, on the first start.
- **Activation is always yours to do.** Nothing activates by itself; you enter your key once per computer.
- **In a folder you have not trusted** (VS Code's Restricted Mode), the extension stays switched off.
- **ai2fm talks only to approved ai2fm servers, over HTTPS.** A project folder cannot redirect your scripts or your licence anywhere else.
- **Compiled with Bytenode.** The extension ships as compiled code for your editor's exact runtime.
- **Responses are size-limited and time-limited**, and unused code was removed.

## Installing v2.5

1. **Update your editor first: run "Check for Updates".** v2.5 is compiled for the exact runtime of each supported editor. An out-of-date editor cannot load it.
2. **Install** the extension from the file in your ai2fm email: **Extensions → … → Install from VSIX**.
3. Click the **ai2fm icon** in the left-hand bar, then **Enter License Key**. Updating from v2.4? Your key is already filled in: press Enter.
4. **Licence holders:** in the panel, **Help → Install Agent Pack…**, and choose the pack's ZIP file. Then, for your AI agent, **Add to Workspace**.

**Supported editors:** VS Code · Cursor · Devin · Antigravity IDE · Kiro · VSCodium · TRAE · Qoder, on Windows (x64) and macOS (Intel).

## Good to know

- **If your editor updates and ai2fm stops loading,** the new editor build ships a runtime the release was not compiled for. We publish a build for it. Until then, keep the editor on the version you had.
- **A bare `#` is a blank line.** FileMaker has no empty comment: an empty `#` line pastes as a blank line and comes back as an empty line.
- **The name in parentheses after a layout** (Go to Layout, Go to Related Record) is the layout's name repeated, not its table occurrence. No script carries the table occurrence.
- **Linux:** you can edit `.fmscript` and FileMaker XML, but FileMaker's clipboard needs macOS or Windows.
